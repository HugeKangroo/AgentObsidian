# Status

Date: 2026-05-10

Current phase: LLM Wiki core + Obsidian canonical vault. Kuzu has been removed from the required dependency set, package runtime, tests, local environment, and generated project artifacts.

Goal: build a usable local knowledge-compounding product that agents can operate through raw evidence, a human-readable Obsidian vault, compiler validation, derived search/ranking, context packs, and MCP tools.

Current layout: the runnable Python package lives in `knowledge-system/`, while the configured Obsidian vault lives in `vaults/main/`. The default mapping is stored in `knowledge-system/agentobsidian.json` and can be overridden with `--vault-path` or `AGENT_OBSIDIAN_VAULT_PATH`.

## Completion Assessment

Current machine-gated completion: 100.0% under `completion-gates-v1` after importing the full local X bookmark CSV, applying the first real info-distillation draft, correcting blocked-synthesis ranking, and recording a compact linked-evidence batch follow-up decision for the full X backlog.

The earlier 65% estimate was a broad maturity judgment before the release gates were made executable. The current score is generated by `ks completion-audit`; it is stricter where blockers are machine-visible and more generous where contracts already exist and pass checks.

This is not a prototype skeleton anymore. The core vault-native workflow is usable: info-oriented intake, raw evidence preservation, source-card provenance, Obsidian-readable knowledge pages, compilation/linting, search/ranking, graph-derived signals, info/synthesis task bundles, proposal review, MCP runtime tools, linked evidence worklists, media annotations, and cleanup readiness signals all exist and have regression coverage.

The system previously satisfied the committed `completion-gates-v1` release gate on the seed corpus. After full local X bookmark import, the score intentionally dropped because thousands of real linked evidence items became visible as pending work. The current system now distinguishes silent pending evidence from an explicit review decision: the 3953 imported backlog items are recorded as `needs_followup` in one Obsidian-readable batch decision artifact, so future capture/review agents can continue without pretending the linked content has already been captured.

Completion by layer:

- Architecture and source-of-truth model: 100%.
- Obsidian vault readability and canonical page workflow: 100%.
- Raw evidence preservation and provenance: 100%.
- CLI tooling: 100%.
- MCP runtime surface for local agents: 100%.
- Hybrid search and ranking: 100% for the current seed eval set; blocked draft synthesis pages are demoted below cleaner maintained pages.
- Agent synthesis and proposal workflow: 100%.
- Linked evidence expansion and media/repo follow-up: 100% under the current gate; 3960 linked evidence items have explicit status, 7 are captured/reviewed, and 3953 are preserved as `needs_followup` backlog through a compact batch decision.
- Cleanup readiness for X bookmarks: 100%.
- Production automation, monitoring, and continuous operation: 100%.

Current blocking layers: none under `completion-gates-v1`; current status is `healthy`. This means the system state is explicit and operable, not that every external/media link has been deeply captured.

## Completed Current Slice

- Representative X bookmark sources rebuild into canonical `vault/raw/`, `vault/wiki/`, `vault/maps/`, and `vault/reviews/`.
- Local X bookmark captures from `data/bookmarks-classified.csv` can be imported into the vault as raw evidence and human-readable source cards through `ks vault-import-x-bookmarks`; the 6-row rebuild remains a regression fixture, not the production import path.
- The current main vault has imported the local X CSV: 1980 new bookmark source cards/raw captures were added, while 6 existing curated sample source cards were skipped.
- The processing contract has been corrected to `InfoUnit`: agents should process normalized info directly, while source cards remain provenance/backlink views.
- A real Codex-authored info-distillation draft was applied to the main vault as `[[Agent Evaluation Readiness Feedback Loop]]`, creating a readable synthesis page from two info units and preserving three review blockers.
- Vault compiler parses Markdown frontmatter, wikilinks, backlinks, raw manifests, review pages, tags, aliases, embeds, and callouts.
- Derived search/ranking uses SQLite FTS5, deterministic `hashing-token-v1` vectors, and Obsidian-link graph ranking.
- Vault-native webpage/PDF/repo intake writes raw captures and source cards into the Obsidian vault.
- Agent-mediated info processing builds task bundles from normalized info units and applies validated drafts through the vault boundary; source cards are evidence anchors, not the target summaries.
- Agent-mediated synthesis builds context packs and applies validated drafts through the vault boundary: new synthesis pages can be created directly as drafts, while updates to existing pages create reviewed proposals.
- Agent synthesis task bundles include source-card/raw-manifest evidence checklists, claim-support instructions, required Obsidian/math/modeling draft structure, and a `claim_support` schema field.
- Reviewed page-update proposals are implemented under `vault/proposals/`; proposals can be linted, accepted into canonical pages, or rejected while remaining auditable.
- Reviewed page-update proposals now include Obsidian-readable Evidence Context with source-card links and raw manifest paths; proposal lint blocks missing evidence context before accept.
- Hybrid retrieval can persist generated retrieval traces and run a local retrieval evaluation set; current sample eval is 5/5 top-1 after demoting source cards below maintained knowledge pages for general queries.
- Hybrid ranking demotes synthesis pages with unresolved review blockers so a draft generated from the same topic does not outrank a cleaner maintained knowledge page.
- Intake now records a source score on source cards and intake results, covering relevance, novelty, evidence completeness, actionability, total score, decision, and reasons.
- Linked external/media evidence is normalized into `vault/generated/linked_evidence_queue.json` so follow-up capture work has a concrete queue instead of being buried only in review prose.
- Linked evidence capture worker is implemented for queue items: webpage links can be captured into the vault, media links can preserve raw assets from either an explicit local media path or explicit `download_media` fetch, and repo links can be captured from either an explicit local clone path or explicit `clone_repo` fetch.
- Linked evidence queue state is reconciled into `vault/generated/linked_evidence_status.json`, merging queue items with capture results and review decisions as `pending`, `captured`, `unsupported`, `decided`, or `needs_followup`.
- Linked evidence decisions can be recorded as Obsidian-readable single-item or batch review artifacts and are merged back into the generated status index for cleanup readiness.
- A compact batch decision artifact now marks the full imported X linked-evidence backlog as `needs_followup`: 3953 items are no longer silent pending work, and the decision remains non-destructive.
- Source cleanup readiness report is implemented as a generated, non-destructive report that explains which sources are ready or blocked before any X bookmark cleanup workflow.
- Cleanup candidate emission is implemented as non-destructive `deletion_candidate` review files plus a generated candidate index; it does not delete bookmarks or raw evidence.
- Release-gate completion audit is implemented as `ks completion-audit` and MCP `get_completion_audit`; it writes `vault/generated/completion_audit.json` using `completion-gates-v1`.
- Linked evidence follow-up for the current queue is closed at the queue level: 7 total, 7 captured, 7 decisions, 0 pending, 0 unsupported.
- Parent missing-evidence review blockers can be resolved from linked evidence decisions through `ks linked-evidence-resolve-reviews` and MCP `resolve_linked_evidence_reviews`; the real vault resolver run resolved 5 parent blockers while preserving the X video follow-up blocker.
- Batch intake is implemented through `ks batch-intake` and MCP `run_batch_intake` for webpage, PDF, repo, and media manifests.
- Health reporting is implemented through `ks health-check` and MCP `get_health_report`; it writes `vault/generated/health_report.json`.
- Agent synthesis now has explicit target-page selection for choosing maintained non-source anchor pages for reviewed updates.
- New PDF/repo/media/web raw manifests include `source_card_path`; existing vault manifests were backfilled with that metadata.
- Captured media evidence writes `vault/raw/media/`, a source card, an Obsidian-readable media page with an embedded local asset, and a review blocker for caption/OCR or human interpretation.
- Media annotation writeback is implemented: human or agent captions/observations create Obsidian-readable annotation pages and can resolve matching media review blockers without mutating the original media page.
- Linked evidence pages are conservatively demoted in hybrid ranking until they are reconciled into maintained knowledge pages, preventing captured evidence from outranking accepted wiki pages.
- FastMCP runtime exposes vault-native tools for search, compile, page/map/backlink reads, context packs, intake, info task preparation/apply, synthesis draft apply, lint, and deletion-candidate signals.
- Kuzu modules, migration code, old kernel/reconcile paths, old Kuzu tests, local `knowledge.kuzu`, backup files, and the installed `kuzu` package were removed.
- Vault path resolution is centralized. The system no longer requires the Obsidian vault to live under the Python package directory.
